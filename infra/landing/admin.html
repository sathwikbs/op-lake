Administrators only · privileged / break-glass tools

Data Platform — Admin Console

Privileged tooling that sits above or outside the per-user data governance a regular user sees on the main launchpad →. Each tool enforces its own authentication; only the platform-admin persona should use these.

Heads up: these tools can bypass or reconfigure Unity Catalog governance (raw storage, identity provider, secret store). Use for administration / break-glass only — day-to-day data work happens through the governed tools on the main launchpad, where UC enforces your grants.

⚑ First-run admin tasks (do these before real use)

  • Reset the break-glass admin password. platformadmin is forced to reset on first login (its repo-seeded password is single-use).
  • Reset or disable the seeded demo accounts. engineer and engineer2 are also forced to reset on first login. analyst is the smoke-test fixture (kept usable for the harness) — disable or delete it in any real deployment in Keycloak → Users.
  • Connect your org SSO. Keycloak → Identity Providers → add OIDC/SAML, then map the org's groups to analysts / data-engineers / platform-admins. The IAM reconciler turns group membership into Unity Catalog grants automatically.
  • Then lock down local login. Once org SSO works, disable local demo users and (optionally) local password login, keeping platformadmin as break-glass.

Access & hardening notes

  • Individually gated: every linked tool authenticates independently (Keycloak SSO, MinIO policy, Dagster oauth2-proxy, Keycloak admin login).
  • Recommended next step: put this page itself behind an oauth2-proxy restricted to the platform-admin group (same pattern as the Dagster UI), so non-admins can't even load the admin console index.
  • Least exposure: MinIO and Vault are on isolated networks; only the gateway + the services that need them can reach them. Nothing here hands out static storage keys.
